# Netcore N30 Pro 固件反馈:请求补充编译缺失的内核模块(openclash / passwall 无法安装)

## 结论先行

当前固件(`r37877-n30pro`)在安装 openclash 和 passwall 时均报错,依赖的若干内核模块在整个软件源(镜像源 `mirrors.vsean.net` 及官方源 `downloads.immortalwrt.org`)中**完全不存在**(不是版本不匹配,是仓库里压根没有这个包)。经排查,这是 **mediatek/filogic 平台官方内核编译配置本身就没有勾选这几个模块**导致的上游缺失,不是本次定制固件独有的问题,但既然本次是为这台设备单独编译,希望能顺手把这几个模块的编译选项加上。

---

## 一、问题复现

### 1. 已补全软件源仓库分类

首先确认过不是仓库分类缺失的问题——已经把 `distfeeds.list` 补齐为包含 `base`、`luci`、`packages`、`routing`、以及对应 `targets/mediatek/filogic` 全部分类,`apk update` 后可用包总数从 4780 增加到 9589,排除了仓库配置不全的可能性。

### 2. 安装 openclash 报错

```
apk add luci-app-openclash
```

报错:
```
依赖的软件包 kmod-inet-diag 在所有仓库都未提供。
依赖的软件包 kmod-nft-tproxy 在所有仓库都未提供。
依赖的软件包 kmod-tun 在所有仓库都未提供。
```

### 3. 安装 passwall 报错

```
apk add luci-app-passwall luci-i18n-passwall-zh-cn
```

报错(比openclash多两个,因为passwall新版把sing-box作为强依赖):
```
依赖的软件包 kmod-nft-socket 在所有仓库都未提供。
依赖的软件包 kmod-nft-tproxy 在所有仓库都未提供。
依赖的软件包 kmod-inet-diag 在所有仓库都未提供。
依赖的软件包 kmod-netlink-diag 在所有仓库都未提供。
依赖的软件包 kmod-tun 在所有仓库都未提供。
```

### 4. 直接搜索确认,仓库里确实没有这些包(不是版本不匹配)

```
apk search kmod-tun
apk search kmod-nft-tproxy
apk search kmod-inet-diag
apk search kmod | grep -i tun
```
以上四条命令**全部返回空结果**,证实这几个包在当前软件源里根本不存在,不是ABI/内核指纹不匹配导致的"不可用",是仓库里没有这个条目。

## 二、请求补充编译的内核模块清单

| 模块名 | 用途 | 被谁依赖 |
|---|---|---|
| `kmod-tun` | TUN虚拟网卡,clash/sing-box的tun透明代理模式需要 | openclash(通过sing-box)、passwall(通过sing-box) |
| `kmod-nft-tproxy` | nftables的TPROXY透明代理支持 | openclash、passwall的TPROXY运行模式 |
| `kmod-nft-socket` | nftables socket匹配,配合tproxy使用 | passwall |
| `kmod-inet-diag` | inet连接状态诊断,sing-box等程序查询连接状态用 | openclash(sing-box)、passwall(sing-box) |
| `kmod-netlink-diag` | netlink诊断 | passwall(sing-box) |

这几个都是标准的OpenWrt内核模块,在 `make menuconfig` 的 `Kernel modules → Network Support` 分类下可以直接勾选,**不涉及DTS或硬件相关的定制修改**,属于纯软件层面的编译配置调整,预计工作量不大。

## 三、临时替代方案(已验证部分可行,供参考)

在等待固件更新期间,已经手动验证了不依赖上述内核模块的临时方案:

- **手动配置xray-core**,走REDIRECT(非TPROXY)模式,不需要`kmod-tun`/`kmod-nft-tproxy`。经测试:
  - trojan协议认证、TLS握手均正常
  - 访问 `bing.com` 等网站正常(HTTP 200)
  - 访问 `google.com`、`wikipedia.org` 时连接卡死超时(TCP连接建立、少量数据交换后无响应,非RST/FIN,是静默无响应)
  - 同一节点在另一台设备(标准编译固件+OpenClash)上访问上述所有网站均无异常
  - 已确认不是MTU问题(已对F50接口做MSS clamping降到1350字节,大数据包能正常双向传输,bing.com测试中可见1300+字节包正常收发)

这个现象目前尚未定位根因,不确定是REDIRECT模式本身在某些数据模式下的局限,还是其他配置细节差异,**该问题独立于本次内核模块缺失反馈,仅供参考**。如果补充编译了上述模块、能够正常安装openclash/passwall(使用完整TPROXY+TUN模式)后,这个"部分网站访问异常"的现象是否还会出现,到时候可以一并验证,如果模块补齐后问题依然存在,再单独反馈定位。
