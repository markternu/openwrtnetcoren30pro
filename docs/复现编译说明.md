# 复现编译说明(可选)

> 本次实际编译环境:macOS 上以 Lima 起 Ubuntu 24.04(x86_64)虚拟机,
> 源码放在 Linux 本地 ext4(大小写敏感),`make -j8`,整机从零约 3-4 小时。
> 下面是**实测踩过并已修好的 5 个编译障碍**,照此可一次编过。

## 一、编译期必须做的 4 处调整(实测)

| # | 问题 | 处理 |
|---|---|---|
| 1 | 默认 `CONFIG_USE_LLVM_BUILD=y` 会额外编译一整套 host LLVM/clang(4 千多个目标,曾在 12GB 内存下被 OOM kill) | `.config` 改 `# CONFIG_USE_LLVM_BUILD is not set`(内核用 GCC 编,功能不受影响;若要 clang 内核则需把 VM 内存加到 20G+) |
| 2 | `bridger`(BPF 桥加速,ImmortalWrt 默认包)依赖 `bpf-headers`,而它必须要 clang ≥12;关掉 LLVM 后 `/invalid/clang` 报错 | 关掉 `CONFIG_PACKAGE_bridger`(与 USB 无关),同时关 `CONFIG_HAS_BPF_TOOLCHAIN/CONFIG_NEED_BPF_TOOLCHAIN` |
| 3 | `base-files` 的 ipk 风格版本号 `$(PKG_RELEASE)~$(REVISION)` 含 `~`,而本版本以 **apk** 打包,apk 拒绝(报 `package version is invalid`) | 打补丁:`package/base-files/Makefile` 第 49/259 行改为 `$(PKG_RELEASE)-r1`(见 `patches/base-files-apk-version.patch`) |
| 4 | `luci-base` 依赖 `cgi-io`,而该包在 packages feed(本次没克隆整个 feed) | 从 `immortalwrt/packages`(分支 `openwrt-25.12`)取 `net/cgi-io/Makefile` 放到 `package/net/cgi-io/`,并在 `.config` 里 `CONFIG_PACKAGE_cgi-io=y` |
| 5 | 源码无 `.git`,版本回落成 `~unknown`,同样被 apk 拒绝 | `make` 时传 `REVISION=r37877-n30pro` |

## 二、完整命令

本固件基于 SamZong233/immortalwrt **commit 3c71dfc2b6**(即 V2 固件的真实源码,内核 6.12,与已刷入的
r37877-3c71dfc2b6 一致),在其上仅打两处补丁后编译。若你想自行复现:

```bash
# 1) 取源码
git clone https://github.com/SamZong233/immortalwrt.git
git checkout 3c71dfc2b67dc7808d110afa66d66527f4b2ce2e

# 2) 打补丁(本目录 patches/)
cp patches/mt7981b-netcore-n30pro.dts target/linux/mediatek/dts/mt7981b-netcore-n30pro.dts
patch -p1 < patches/filogic-mk-device-packages.patch   # 或手工改 DEVICE_PACKAGES 行

# 3) 最小配置
cat > .config <<'EOF'
CONFIG_TARGET_mediatek=y
CONFIG_TARGET_mediatek_filogic=y
CONFIG_TARGET_mediatek_filogic_DEVICE_netcore_n30pro=y
CONFIG_TARGET_PER_DEVICE_ROOTFS=y
CONFIG_TARGET_ROOTFS_SQUASHFS=y
EOF

# 4) 依赖:OpenWrt 构建仅支持 Linux/大小写敏感文件系统。
#    Ubuntu/Debian:  apt install build-essential clang flex bison gawk gettext git \
#        libncurses5-dev libssl-dev python3 rsync swig unzip zlib1g-dev file wget curl

# 5) feeds(本固件只需要 luci;其余 feed 未使用)
./scripts/feeds update luci
./scripts/feeds install -a -p luci

# 6) 编译(首次含工具链+内核,耗时较长)
make defconfig
make -j$(nproc) V=s

# 7) 产物
# bin/targets/mediatek/filogic/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb
```

> DEVICE_PACKAGES 已含:luci/luci-ssl/中文语言包、kmod-usb3、usb 存储、usb-net
> (cdc_ether/rndis/cdc_ncm)、usb-acm、block-mount 等;USB 供电由 DTS 的 GPIO23
> regulator + `vbus-supply` 修复(见 netcore-n30pro-usb.dts.patch)。

## 八、第三轮补充:编译"默认不选"的内核模块(openclash/passwall 依赖)

这几个 kmod 的符号默认不选(`DEFAULT:=m if ALL_KMODS`),只加进 `DEVICE_PACKAGES` 是不够的,
`make defconfig` 不会自动选中它们,必须显式写进 `.config`:

```sh
for s in kmod-tun kmod-nft-tproxy kmod-nft-socket kmod-nf-tproxy kmod-nf-socket \
         kmod-inet-diag kmod-netlink-diag; do
    sed -i "s|^CONFIG_PACKAGE_${s}=.*|CONFIG_PACKAGE_${s}=y|" .config
    grep -q "^CONFIG_PACKAGE_${s}=y" .config || echo "CONFIG_PACKAGE_${s}=y" >> .config
done
```

⚠️ **内核配置一变,内核包哈希就变**,所有内核模块包必须重编,否则 install 阶段会报
`kernel-6.12.91~<新哈希> breaks: kmod-xxx[..~<旧哈希>]`:

```sh
make package/kernel/linux/clean package/kernel/mt76/clean \
     package/kernel/mac80211/clean package/kernel/gpio-button-hotplug/clean
make package/network/utils/fullconenat-nft/clean     # 该包不在 package/kernel/ 下,容易漏
rm -rf staging_dir/packages/mediatek
make -j8 V=s REVISION=r37877-n30pro
```

另注:`kmod-ipt-tproxy` 会拉起整条 iptables 内核模块链(`kmod-ipt-core` 等),本轮未纳入;
若需要 iptables 模式,连同依赖一起加即可。
