# 喂饭级教程:从快递到上网(树莓派从零 + 路由器从原厂系统)

> 这份文档写给**完全没接触过刷机的人**。你不需要懂 Linux、不需要懂 u-boot、不需要懂 UBI。
> 只要照着抄命令、对照"应该看到什么",就能把一台**刚拆封的原厂 Netcore N30 Pro** 刷成本项目的定制固件,
> 并且用**一条中兴 F50** 让它上网。
>
> 全程分两条线:
> * **第一部分:树莓派从零** —— 用一台树莓派当 TFTP 服务器(刷机的"送料机")。
> * **第二部分:路由器从原厂系统开始** —— 备份 → 换 u-boot → 刷固件 → 初始化 → F50 上网。
>
> 不想看原理也行,但**第 0 章的"后悔药"一定要做**。

## 第 0 章 开箱前必读

### 0.1 你会得到什么

* 一台能正常用 **USB 口**的 N30 Pro(插 U 盘、插手机、插随身 WiFi 都能识别);
* 插上**中兴 F50** 就能让全家设备上网;
* 4 个 LAN + 1 个 WAN 全部可用;
* 带 LuCI 中文网页后台,随时能装 OpenClash / PassWall 等插件。

### 0.2 物料清单

| 物料 | 说明 | 必需? |
|---|---|---|
| Mac / 任意电脑 | 用来烧卡、SSH、下物料 | ✅ |
| 树莓派 4B(3B+/Zero2W 也可,要有网口) | 当 TFTP 服务器 | ✅ |
| microSD 卡 ≥8GB + 读卡器 | 树莓派系统盘 | ✅ |
| 树莓派电源 5V/3A | 供电不足会随机死机 | ✅ |
| 网线 ×2 | ① 树莓派 ↔ 路由器 ② 电脑 ↔ 路由器/家里网络 | ✅ |
| 中兴 F50 随身 WiFi | 当 WAN 用 | ✅ |
| USB-TTL 串口模块(CH340/CP2102 等) | 只在"路由器变砖/必须拆机救"时用 | ⬜ 选配 |
| 小十字螺丝刀 | 拆路由器外壳(走 TTL 路线才需要) | ⬜ 选配 |

> 树莓派不是必须的 —— 任何能跑 TFTP 的 Linux 机器都行(旧笔记本装 Ubuntu 也可以)。
> 但**树莓派最省事**,本教程按树莓派写。

### 0.3 拓扑(先看懂这张图)

```
                 ┌──────────── 家里 WiFi(能上网)────────────┐
                 │                                          │
   [MacBook] ────┘(WiFi/SSH)                                │
        │                                                   │
        │ SSH 到树莓派的 wlan0 IP(例 192.168.1.165)          │
        ▼                                                   │
   [树莓派]                                                  │
     ├── wlan0 ──→ 家里 WiFi(上网用)                        │
     └── eth0  ──网线──→ [N30 Pro 路由器]                    │
             静态 192.168.1.254        u-boot 里 IP 192.168.1.1
             (TFTP 服务器)             (刷机时进恢复模式)
```

**一句话记住三件事:**

1. **Mac 永远通过 WiFi 连树莓派**(不要用接路由器那条网线去 SSH,不然你会把自己锁在外面);
2. **树莓派的 eth0 专门负责和路由器点对点**(TFTP 送固件);
3. 路由器在 u-boot 恢复模式下,自己会主动来树莓派这里"取"固件。

### 0.4 时间与难度

| 阶段 | 时间 | 难度 |
|---|---|---|
| 树莓派从零到 TFTP 就绪 | 60–90 分钟(含下载系统) | ⭐ |
| 原厂系统备份 | 20–30 分钟 | ⭐ |
| 换 u-boot | 20–40 分钟 | ⭐⭐⭐(唯一高风险) |
| TFTP 整刷固件 | 15–30 分钟 | ⭐⭐ |
| 初始化 + F50 上网 | 20–30 分钟 | ⭐ |

### 0.5 🚨 后悔药(务必先做)

三件事,顺序不能反:

1. **备份原厂全部分区**(第 B2 章)——尤其是 `mtd5_ubi.bin`,它是"整个原厂系统";
2. **备份原厂 FIP(u-boot)**(第 B2 章)——换 u-boot 前必须留底;
3. **不要在原厂 u-boot 下直接刷第三方固件** —— 它有一套私有签名校验,会拒绝并提示
   `Image slot 0/1 was marked invalid`,严重时会反复进 failsafe。**必须先换 u-boot**。

> ⚠️ 刷机有风险。本项目在真机上验证过"刷机不变砖"(固件只写 `ubi` 分区,不碰 BL2/FIP),
> 但**换 u-boot 这一步是唯一会写引导区**的操作,请务必先备份、并准备好 TTL 救援手段。

### 0.6 名词速查(看不懂就回来查)

| 名词 | 白话解释 |
|---|---|
| **TFTP** | 一种"极简文件传输"协议。u-boot 只会这一种,所以刷机要搭个 TFTP 服务器给它送文件 |
| **u-boot** | 路由器开机后运行的"引导程序",负责找系统、启动系统。刷机的前提 |
| **固件 / 系统** | 路由器真正运行的操作系统(本项目是 ImmortalWrt) |
| **.itb** | 固件镜像文件格式(FIT 打包:内核 + 设备树 + 根文件系统) |
| **initramfs.itb** | "只跑在内存里"的临时系统,不写 flash,用来试探/救援 |
| **sysupgrade.itb** | 正式固件,会写进 flash |
| **UBI / fit 卷 / rootfs_data 卷** | 路由器 flash 里的分区与"卷"。`fit` 卷放固件(引导程序从这里启动),`rootfs_data` 卷放你的配置 |
| **sysupgrade** | 在**已运行的系统里**升级固件(像手机 OTA) |
| **TFTP 整刷** | 让 u-boot 从 TFTP 服务器取固件并写入 flash(像"重装系统") |
| **SSH** | 远程命令行登录。`ssh 用户名@IP` |
| **LuCI** | OpenWrt 的网页后台 |

# 第一部分 树莓派从零开始

> 目标:树莓派变成一台"插上网线就能给路由器送固件"的 TFTP 服务器。
>
> 本部分用到的脚本来自本仓库 [`flash-kit/`](../flash-kit/)。
> 用户名统一用 **`mypi`**,请照抄(自己改了要把命令里的名字对应替换)。

## A1 烧录树莓派系统

### A1.1 装烧录工具

Mac 上打开 <https://www.raspberrypi.com/software/> 下载安装 **Raspberry Pi Imager**。

> 别用 balenaEtcher —— 本项目的实战记录里它就是踩坑源头(镜像明明完好却报错)。

### A1.2 烧录(重点是"预配置",能省掉接显示器的麻烦)

1. 插上 SD 卡(读卡器);
2. Imager 里依次选:
   * **Choose Device** → Raspberry Pi 4(你是别的型号就选对应的)
   * **Choose OS** → `Raspberry Pi OS (other)` → **Raspberry Pi OS Lite (64-bit)**
     (Lite = 无桌面,省资源;我们只需要命令行)
   * **Choose Storage** → 你的 SD 卡(**别选错成硬盘!**)
3. 点右下角的**齿轮 / "编辑设置"**,填:

| 设置项 | 填什么 |
|---|---|
| 主机名 | `raspberrypi` |
| 用户名 | `mypi`(照抄,教程里都用这个名字) |
| 密码 | 自己设一个记得住的 |
| 无线局域网 | 家里 WiFi 的 SSID + 密码,国家选 `CN` |
| 语言环境 | 时区 `Asia/Shanghai`,键盘 `us` |
| 服务 | ✅ 勾选 **Enable SSH** → 选 **Use password authentication** |

4. 点 **Write**,等它写完(会自动校验);
5. 拔卡,插回树莓派,接电源开机。**先不用插网线**(走 WiFi 就能连上)。

> 第一次开机要 1–3 分钟:自动扩容 + 重启一次,耐心等。

## A2 找到树莓派 IP 并 SSH 登录

在 Mac 的"终端"里逐条试(成功一条就够):

```sh
# 方法1:直接用主机名(装了 Bonjour 的 Mac 通常最省事)
ssh mypi@raspberrypi.local

# 方法2:ping 主机名
ping -c 3 raspberrypi.local

# 方法3:家里路由器后台 → DHCP 客户端列表 → 找 raspberrypi

# 方法4:扫局域网(Bonjour 服务发现)
dns-sd -B _ssh._tcp        # 看到实例名后按 Ctrl+C,再用名字解析
```

第一次连接会问:

```
The authenticity of host '...' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

→ 输 `yes` 回车,然后输你设置的**密码**(输入时不显示,正常)。

看到这类提示就成功了:

```
mypi@raspberrypi:~ $
```

**记下树莓派的 WiFi IP**(后面 Mac 一直用它 SSH):

```sh
ip -br addr show wlan0
# 例:wlan0  UP  192.168.1.165/24
```

> 📌 从这一刻起:**Mac 只用这个 WiFi IP 连树莓派**。

## A3 树莓派基础设置

```sh
# 1) 更新系统(第一次会久一点)
sudo apt update && sudo apt full-upgrade -y

# 2) 看一眼网络

# 3) (可选)改时区/主机名/键盘

# 4) (可选但推荐)给 Mac 配免密登录:Mac 上执行

```

### A3.1 ⭐ 第一件事:一键装 oh-my-zsh

树莓派新系统装好后的**第一个安装任务**(和路由器那边保持一致):

```sh
# 任选其一(树莓派通常自带 wget 或 curl)
sh -c "$(curl -fsSL https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/install.sh)"
sh -c "$(wget -qO-  https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/install.sh)"
```

装完 `exec zsh` 即可。完整说明(参数、镜像、卸载、空间提醒)见
[第 B5.2 节](#b52-️-第一个安装任务一键装-oh-my-zsh)。

### A3.2 ⭐ 第二件事:一条命令装好刷机工具包 + TFTP + 固件

```sh
BASE=https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main
sh -c "$(wget -qO- $BASE/install-extras.sh)" -- --with-flash-kit --with-tftp --with-firmware
```

它会把刷机脚本放到 `~/n30kit/`,装好 TFTP 服务,并把**最新固件下载+校验+放进 `/srv/tftp`**。
做完这一步,直接跳到 [A5 打开救砖网络](#a5-打开救砖专用网络三个大坑)。

> 想自己一步一步来(理解原理、排错),看下面的 A4。

> 💡 如果 `apt` 很慢:换国内源(`sudo sed -i 's|raspbian.raspberrypi.org|mirrors.tuna.tsinghua.edu.cn/raspbian|' /etc/apt/sources.list`),

## A4 安装 TFTP 服务并把固件放进去

### A4.0 先判断:树莓派现在能上外网吗?

```sh
ping -c 2 223.5.5.5        # 或者:curl -sI https://github.com | head -1
```

* **能通** → 走 [A4.2 情况一(推荐)](#a42-情况一推荐树莓派自己下载一条命令搞定)。
  99% 是这种情况 —— 因为装 `tftpd` 本来就要联网。
* **不通** → 走 [A4.3 情况二(Mac 中转)](#a43-情况二树莓派没网mac-中转)。

> 本项目仓库是**公开**的,所以树莓派直接 `curl`/`wget` 就能从 Releases 下载,
> **不需要登录、不需要 token、不需要 gh 命令**。

### A4.1 把刷机脚本弄到树莓派(二选一)

> 💡 更省事:直接跑 [A3.2 的一条命令](#a32-️-第二件事一条命令装好刷机工具包--tftp--固件),
> 它会把下面这些全做完。**下面是想手工做/排错时看的版本。**

**情况 A(树莓派能上网,推荐)**:树莓派自己从仓库拉,连 Mac 都不用

```sh
# 在树莓派上执行(SSH 进去之后)
mkdir -p ~/n30kit && cd ~/n30kit
for f in pi-setup-tftp.sh pi-fetch-firmware.sh pi-net-on.sh pi-net-off.sh verify-after-boot.sh; do
    curl -fsSLO https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/flash-kit/$f
done
ls -la
```

**情况 B(树莓派不能上外网)**:Mac 上先克隆/下载本仓库,再把脚本 scp 过去

```sh
# Mac 上:
git clone https://github.com/markternu/openwrtnetcoren30pro.git
scp -O openwrtnetcoren30pro/flash-kit/*.sh mypi@raspberrypi.local:/tmp/
```

### A4.2 情况一(推荐):树莓派自己下载,一条命令搞定

```sh
ssh mypi@raspberrypi.local

# 1) 装 TFTP 服务(只需一次)
sudo sh ~/n30kit/pi-setup-tftp.sh

# 2) 从本项目 GitHub Releases 下载官方固件 → 自动校验 sha256 → 直接放进 /srv/tftp
sudo sh ~/n30kit/pi-fetch-firmware.sh --install
```

`pi-fetch-firmware.sh` 会自动:

1. 查询**最新 Release**(查不到就回落到 `v1.0.0`);
2. 下载 `SHA256SUMS` 与两个 `.itb`;
3. **用 `sha256sum -c` 自动校验**(对不上会直接报错,不会让你刷到坏文件);
4. `--install` 时复制进 `/srv/tftp` 并重启 TFTP 服务。

常用参数:

```sh
--with-uboot                         # 顺便下载"从原厂系统开始"要用的官方 u-boot FIP
--version v1.0.0                     # 指定版本(不取 latest)
--base-url https://<镜像前缀>/https://github.com    # 国内网络慢时走镜像
--dest /tmp/xxx                      # 指定下载目录(默认 /tmp/n30pro-firmware)
```

### A4.3 情况二(树莓派没网):Mac 中转

```sh
# Mac 上:从仓库 Releases 页面下载这三个文件
#   immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb
#   immortalwrt-mediatek-filogic-netis_nx30v2-initramfs.itb
#   SHA256SUMS
# 校验后传过去:
cd ~/Downloads
shasum -a 256 -c SHA256SUMS 2>/dev/null | grep netis_nx30v2 ||   shasum -a 256 immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb
scp -O immortalwrt-mediatek-filogic-netis_nx30v2-*.itb mypi@raspberrypi.local:/tmp/

# 树莓派上:装服务 + 放入固件
ssh mypi@raspberrypi.local
sudo sh /tmp/pi-setup-tftp.sh /tmp/immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb \
                               /tmp/immortalwrt-mediatek-filogic-netis_nx30v2-initramfs.itb
```

### A4.4 手工版(想懂每一步在干什么就看这段)

```sh
sudo apt install -y tftpd-hpa tcpdump curl

sudo mkdir -p /srv/tftp && sudo chmod 755 /srv/tftp
sudo tee /etc/default/tftpd-hpa > /dev/null <<'EOF'
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/srv/tftp"
TFTP_ADDRESS="0.0.0.0:69"
TFTP_OPTIONS="--secure --create"
EOF
sudo systemctl restart tftpd-hpa

# 直接从公开仓库下载(树莓派能上网时)
cd /tmp
BASE=https://github.com/markternu/openwrtnetcoren30pro/releases/download/v1.0.0
curl -fLO $BASE/immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb
curl -fLO $BASE/immortalwrt-mediatek-filogic-netis_nx30v2-initramfs.itb
curl -fLO $BASE/SHA256SUMS

# 校验(必须 OK)
grep netis_nx30v2 SHA256SUMS > check.txt && sha256sum -c check.txt
rm -f check.txt

# 就位
sudo cp /tmp/immortalwrt-mediatek-filogic-netis_nx30v2-*.itb /srv/tftp/
sudo chown root:root /srv/tftp/*.itb && sudo chmod 644 /srv/tftp/*.itb
ls -la /srv/tftp/
```

### A4.5 PASS 标准

```sh
systemctl is-active tftpd-hpa          # 输出 active
sudo ss -lunp | grep :69               # 能看到 0.0.0.0:69
ls -la /srv/tftp/                      # 固件在里面,14,680,358 字节
sha256sum /srv/tftp/*sysupgrade*.itb   # 等于附录 D 的值
```

### A4.6 下载太慢怎么办(国内网络)

* 优先用 **`--base-url` 走可信镜像**(形如 `https://<你的镜像>/https://github.com/...`);
* 或改成 **Mac/手机热点下载 → scp 到树莓派**(A4.3);
* 树莓派能用有线直连家里路由时,换网线往往比 WiFi 快很多。

## A5 打开"救砖专用网络"(三个大坑)

这一段是**整份教程最容易翻车的地方**。原理可以不懂,但脚本一定要跑。

### A5.1 为什么麻烦

* 树莓派的 `wlan0`(连家里 WiFi)和 `eth0`(连路由器)**常常都在 `192.168.1.x` 网段**;
* 而**待刷的路由器自己也是 `192.168.1.1`**,和家里网关撞车;
* 于是 Linux 不知道该从哪张网卡把 TFTP 的回包发出去 → 路由器一直"只请求、收不到数据"。

### A5.2 三大坑与对应处理

| 坑 | 现象 | 处理(脚本已内置) |
|---|---|---|
| ① 临时路由被刷掉 | `ip route add` 加完过一会儿自己没了 | 把路由**写进 nmcli 连接**(持久化) |
| ② 只设 metric 不够 | `ip route get 192.168.1.1` 仍显示走 `wlan0` | 显式绑定源地址 **`src 192.168.1.254`** |
| ③ `rp_filter` 丢包 | 本机自测成功,路由器却收不到数据 | `rp_filter` 必须为 **0**(设成 2 也会丢!) |

### A5.3 一键脚本

> 脚本在 A4.1 已经拉到树莓派的 `~/n30kit/` 了(没拉就回 A4.1 做一次)。

```sh
# 确保树莓派 eth0 已用网线接到路由器(先接着,不影响)
ssh mypi@raspberrypi.local
sudo sh ~/n30kit/pi-net-on.sh
```

它会把 eth0 设成 `192.168.1.254/24`,把 `192.168.1.1/32` 主机路由写进 NetworkManager,
把 `rp_filter` 归零并固化。

### A5.4 手工版(等价命令)

```sh
# 1) 建一个专用连接:静态 IP + 持久主机路由(注意 +ipv4.routes 这一项是关键)
sudo nmcli con add type ethernet ifname eth0 con-name recovery
sudo nmcli con modify recovery \
    ipv4.method manual ipv4.addresses 192.168.1.254/24 \
    ipv4.gateway "" ipv4.never-default yes \
    ipv4.routes "192.168.1.1/32 0.0.0.0 50" \
    ipv6.method disabled
sudo nmcli con down recovery; sudo nmcli con up recovery

# 2) 消除同网段歧义
sudo ip route del 192.168.1.0/24 dev eth0 2>/dev/null

# 3) 强制绑定源地址
sudo ip route replace 192.168.1.1/32 dev eth0 src 192.168.1.254 metric 50

# 4) 关掉 rp_filter 并固化
echo -e 'net.ipv4.conf.eth0.rp_filter=0\nnet.ipv4.conf.all.rp_filter=0\nnet.ipv4.conf.default.rp_filter=0' \
  | sudo tee /etc/sysctl.d/99-tftp-recovery.conf
sudo /sbin/sysctl -w net.ipv4.conf.eth0.rp_filter=0
sudo /sbin/sysctl -w net.ipv4.conf.all.rp_filter=0
sudo systemctl restart systemd-sysctl

# 5) 确认
ip -br addr show eth0
ip route get 192.168.1.1
cat /proc/sys/net/ipv4/conf/eth0/rp_filter
```

> ⚠️ `sysctl` 不在树莓派默认 PATH 里,要用 `/sbin/sysctl`。

### A5.5 PASS 标准(两条必须同时成立)

```
ip route get 192.168.1.1
→ 192.168.1.1 dev eth0 src 192.168.1.254 uid 1000      ← 走 eth0,源地址 254

cat /proc/sys/net/ipv4/conf/eth0/rp_filter
→ 0
```

**稳定性复检**:等 30~60 秒,什么都不改,再跑一次 `ip route get 192.168.1.1`,
如果又变回 `dev wlan0`,说明路由被刷新了 → 回到 A5.4 第 3 步重做,或临时 `sudo nmcli radio wifi off`
(注意:关 WiFi 后你就不能用 WiFi IP SSH 了,务必先确认有别的通道)。

### A5.6 (可选)本机自测

```sh
sudo apt install -y tftp-hpa
tftp 192.168.1.254 -c get immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb /tmp/selftest.itb
ls -la /tmp/selftest.itb      # 应为 14,680,358 字节
```

> 本机自测通过**不代表**环境 OK(第二轮实测:自测成功,但路由器请求收不到,就是 rp_filter 的锅)。
> 必须 A5.5 + A6 一起过。

## A6 树莓派自检清单(6 项)

刷机前逐项对照,**全 PASS 再去按路由器的 Reset**:

| # | 检查 | 命令 | PASS 标准 |
|---|---|---|---|
| 1 | TFTP 服务 | `systemctl is-active tftpd-hpa` | `active` |
| 2 | 固件就位 | `sha256sum /srv/tftp/*sysupgrade*.itb` | = 附录 D 的值 |
| 3 | eth0 链路 | `ip -br addr show eth0` | `UP` 且带 `192.168.1.254/24` |
| 4 | 路由绑定 | `ip route get 192.168.1.1` | `dev eth0 src 192.168.1.254` |
| 5 | rp_filter | `cat /proc/sys/net/ipv4/conf/eth0/rp_filter` | `0` |
| 6 | 本机自测 | A5.6 | 拉到 14,680,358 字节 |

## A7 树莓派常见问题

| 症状 | 原因 | 解决 |
|---|---|---|
| `ssh: Could not resolve hostname raspberrypi.local` | Bonjour/网络问题 | 去路由器后台找 IP,用 IP 连 |
| SSH 提示 `REMOTE HOST IDENTIFICATION HAS CHANGED` | 重装过系统,指纹变了 | Mac 执行 `ssh-keygen -R raspberrypi.local`(或 -R IP) |
| `apt` 报错、很慢 | 网络/源问题 | 换国内源;或先把需要的包装完再动 eth0 |

| 路由器收不到数据(19 字节包) | ①文件名不对 ②rp_filter ③路由漂到 wlan0 | 对照 A5.5 / 附录 B |

# 第二部分 路由器从原厂系统开始

> 目标:从**刚拆封的原厂系统**,一路走到"USB 口有电 + 中兴 F50 能上网"。
> 本部分会写 flash(刷机),**第 0.5 章的后悔药必须已完成**。

## B0 先认清:分区表与保险

原厂系统的 flash 分区大致如下(进系统后 `cat /proc/mtd` 会看到,编号可能因固件版本略有差异):

| 分区 | 内容 | 能不能动 |
|---|---|---|
| BL2 | 最底层引导(preloader) | ⚠️ 不要动 |
| u-boot-env | u-boot 的环境变量 | 尽量不动 |
| Factory | 出厂校准数据(WiFi 参数、MAC) | ⚠️ 绝对不要动!丢了 WiFi 就废了 |
| FIP | u-boot 本体(BL31 + U-Boot) | 🔧 换 u-boot 时要写这里 |
| ubi | 系统卷(`fit` 卷 + `rootfs_data` 卷) | ✅ 刷固件时写这里 |

**两句话记住:**

* 刷第三方固件**只需要写 `ubi` 分区** → 不会变砖;
* **换 u-boot 要写 `FIP` 分区** → 这是唯一高风险操作,**先备份 FIP**。

## B1 原厂系统:进后台、开 SSH

### B1.1 通电与接线

1. 路由器接电源;
2. 用网线把**电脑**接到路由器的 **LAN 口**(或接到家里网络,让路由器自己 DHCP 也行);
3. 等 1 分钟,指示灯稳定。

### B1.2 进原厂后台

* 浏览器打开 **<http://192.168.0.1>**
* 用户名:**`useradmin`**
* 密码:**你设置的管理密码**(出厂默认见机身贴纸/说明书)

> 注意:原厂默认网段是 `192.168.0.x`,**不是** 1.x。别和刷完后的 `192.168.1.1` 搞混。

### B1.3 打开 SSH(磊科默认不锁 SSH)

后台 → **应用 / 应用管理 → 远程访问** → 打开"局域网 SSH 访问"(端口 **22**)。

然后在 Mac 上:

```sh
ssh useradmin@192.168.0.1
# 如果提示用户名错误,试 root@192.168.0.1
```

能进到 shell(提示符类似 `#` 或 `$`)就成功了。

### B1.4 记录当前状态

```sh
cat /proc/mtd            # 记下分区表(建议截图)
cat /etc/openwrt_release 2>/dev/null || cat /etc/os-release | head
```

## B2 备份原厂全部分区(后悔药)

> 这一步做完,你就有"随时回原厂"的底气。**别跳**。

### B2.1 在路由器上导出到内存

```sh
mkdir -p /tmp/backup
cat /proc/mtd              # 按实际名字对照下面这组(常见是 6 个 mtd)
```

```sh
# 一条条执行;如果 /proc/mtd 显示的分区编号不同,把 dd 里的 mtdN 对应改掉
dd if=/dev/mtd1 of=/tmp/backup/mtd1_BL2.bin
dd if=/dev/mtd2 of=/tmp/backup/mtd2_u-boot-env.bin
dd if=/dev/mtd3 of=/tmp/backup/mtd3_Factory.bin
dd if=/dev/mtd4 of=/tmp/backup/mtd4_FIP.bin
dd if=/dev/mtd5 of=/tmp/backup/mtd5_ubi.bin

ls -la /tmp/backup/        # 确认文件都在、大小不为 0
```

### B2.2 拉回 Mac 保存

```sh
# 在 Mac 上执行(注意 -O,老系统没有 sftp-server,不加会报 Connection closed)
mkdir -p ~/n30pro-backup
scp -O useradmin@192.168.0.1:/tmp/backup/*.bin ~/n30pro-backup/

# 校验并留档
cd ~/n30pro-backup && shasum -a 256 *.bin | tee SHA256SUMS-backup.txt
```

> 💾 把 `~/n30pro-backup/` 再复制到网盘/U 盘一份。**这堆文件就是你最坏的保险**。

## B3 更换 u-boot

### B3.1 为什么必须换

原厂 u-boot 只认自家签名格式的固件。你直接刷第三方固件,它会:

```
Image slot 0/1 was marked invalid
```

然后反复进 failsafe —— 刷多少次都一样。**所以先换 u-boot**。

### B3.2 要用的文件,以及怎么拿到它(按你的网络情况三选一)

需要的文件只有一个:

```
immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip
```

官方下载页:<https://downloads.immortalwrt.org/releases/25.12.0/targets/mediatek/filogic/>

**方式 1(推荐):树莓派上直接下载(它此刻能上网),再传给路由器**

```sh
# 树莓派上:用 A4.1 拉下来的脚本,一次下好固件 + u-boot,并自动核对官方 sha256sums
sudo sh ~/n30kit/pi-fetch-firmware.sh --with-uboot

# 或者手工下:
cd /tmp
U=https://downloads.immortalwrt.org/releases/25.12.0/targets/mediatek/filogic
curl -fLO $U/immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip
curl -fLO $U/sha256sums
grep 'spim-nand-bl31-uboot.fip$' sha256sums > ub.check && sha256sum -c ub.check && rm -f ub.check

# 再传到路由器(原厂系统)
scp -O /tmp/immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip \
       useradmin@192.168.0.1:/tmp/
```

**方式 2:原厂系统本身能上网 → 直接在路由器上下载**

```sh
# SSH 进原厂系统后(原厂系统能上网的话)
cd /tmp
curl -fLO <上面那个完整 URL>
sha256sum immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip
```

**方式 3:Mac 下载 → scp 进路由器**

```sh
# Mac 上
cd ~/Downloads && curl -fLO <上面那个完整 URL>
scp -O immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip \
       useradmin@192.168.0.1:/tmp/
```

> 该 u-boot 与我们的固件完全配套(它请求的 TFTP 文件名就是
> `immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb`)。
> 社区还有带 WebUI/DHCP 的第三方 u-boot(适合不爱敲命令行的人),可按需选择。

### B3.3 路线选择

| 路线 | 需要什么 | 难度 | 建议 |
|---|---|---|---|
| **A. 纯 SSH(不拆机)** | 原厂系统能 SSH | ⭐⭐ | 👍 先试这条 |
| **B. TTL 串口(拆机)** | USB-TTL、螺丝刀 | ⭐⭐⭐⭐ | A 失败/已变砖时用 |

### B3.4 路线 A:纯 SSH 写入 FIP

```sh
# 1) 在 Mac 上把 u-boot 文件传到路由器
scp -O ~/Downloads/immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip \
       useradmin@192.168.0.1:/tmp/

# 2) SSH 进路由器,确认 FIP 分区存在
ssh useradmin@192.168.0.1
cat /proc/mtd | grep -i fip        # 应看到 fip/FIP 对应某个 mtdX

# 3) 写入(把 mtd4 换成你实际看到的 FIP 分区,通常 mtd4;也可用分区名)
mtd write /tmp/immortalwrt-25.12.0-mediatek-filogic-netis_nx30v2-spim-nand-bl31-uboot.fip FIP

# 4) 重启
reboot
```

写完后:

* 正常的话路由器会以新 u-boot 启动,原来系统可能已经起不来(这正常,接下来就刷固件);
* 或断电 → 按住 **Reset** → 上电 10 秒 → 松开,进入 **u-boot TFTP 恢复模式**(这就是我们要的)。

> ⚠️ 写 FIP 期间**绝对不能断电**。若这一步之后发现完全没反应,走路线 B(TTL)救援:
> 用 TTL 进 u-boot 命令行,`tftpboot` 拉 `initramfs.itb` 到内存启动,再用 `mtd write` 重写 FIP。
> TTL 接法:拆开外壳 → 主板背面找到 **■●●●** 四个焊盘(VCC / RX / TX / GND)→
> **只接 RX、TX、GND(不要接 VCC!)** → 串口 115200 8N1。

### B3.5 路线 B:TTL 串口(简述)

1. 拆外壳(外壳 4 颗螺丝 + 主板 4 颗螺丝);
2. 找主板背面 UART 焊盘 ■●●●,杜邦线接 RX/TX/GND;
3. Mac 上 `screen /dev/tty.usbserial-* 115200`(或 `minicom`);
4. 上电看 u-boot 打印,进入命令行;
5. `setenv serverip 192.168.1.254; setenv ipaddr 192.168.1.1`
6. `tftpboot 0x46000000 immortalwrt-mediatek-filogic-netis_nx30v2-initramfs.itb && bootm 0x46000000`
7. 进入内存系统后,把 FIP 传进去并 `mtd write … FIP`。

## B4 TFTP 整刷 ImmortalWrt

前提:**第一部分全部 PASS** + **u-boot 已换**。

### B4.1 开一个抓包窗口(另开 SSH,别复用旧窗口)

```sh
ssh mypi@raspberrypi.local
sudo tcpdump -i eth0 -n -e udp port 69
```

### B4.2 让路由器来取固件

1. **拔掉路由器 WAN 口那根上网线**(避免 `192.168.1.1` 和家里网关撞车);
2. 网线确认:树莓派 `eth0` ↔ 路由器 **LAN 口**(如果抓不到包,换另一个 LAN 口试,不同 u-boot 只点亮某个口);
3. 路由器:**断电 → 按住 Reset → 上电 → 保持约 10 秒 → 松开**;
4. 盯着 tcpdump 窗口。

### B4.3 tcpdump 判读表

| 你看到的 | 含义 | 下一步 |
|---|---|---|
| `RRQ "immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb"`,接着一串 ~1472 字节的 DATA | ✅ 正在刷 | 等它传完 |
| `RRQ "…initramfs.itb"` | u-boot 走的是"启动内存系统"分支 | 进内存系统后手工 `sysupgrade` |
| 只有一问一答的 **19 字节**小包 | ❌ TFTP 报"文件不存在" | 文件名不一致:按 RRQ 里抓到的名字复制改名 |
| 完全没动静 | 链路/路由/rp_filter/端口问题 | 回 A5.5、A6 逐项复查,换 LAN 口 |

### B4.4 传输完成

* 最后一个 DATA 包会**小于 1472 字节**;
* 随后 u-boot 自己执行 `ubi remove fit; ubi create fit; ubi write …`;
* 指示灯会快速闪(写入中)→ **千万别断电** → 写完自动重启(约 1–3 分钟)。

> u-boot 的升级动作等同于"重建 `fit` 卷",所以**一定生效**,不存在"刷了没换"的问题。

## B5 首次开机初始化

> **顺序很重要**:先设密码 → 再装 oh-my-zsh(第一个安装任务)→ 然后才是其他安装与配置。

### B5.1 登录并设密码

```sh
ssh root@192.168.1.1
# 若提示 "There is no root password defined" → 正常,首次没密码
passwd                     # 立刻设置密码(必做!)
```

网页后台:<http://192.168.1.1>(用户名 `root`,密码刚设的)。

### B5.2 ⭐ 第一个安装任务:一键装 oh-my-zsh

刷完新系统的**第一件事**就是把它装上 —— 之后敲命令有高亮、补全、历史记录,舒服很多。

本项目提供 ohmyzsh 风格的一键命令(**仓库是公开的,不需要登录**):

```sh
# OpenWrt 固件默认没有 curl/wget,但一定自带 uclient-fetch —— 用这条零依赖的:
sh -c "$(uclient-fetch -O - https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/install.sh)"
```

装过 curl 或者你的系统有 wget 时,也可以用与 ohmyzsh 完全同款的两条:

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/install.sh)"
sh -c "$(wget -qO-  https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main/install.sh)"
```

脚本会自动完成:装 `zsh`(`+git`、证书)→ 克隆 oh-my-zsh(默认 GitHub 失败自动切 Gitee 镜像)
→ 生成 `~/.zshrc`(原文件备份为 `.zshrc.pre-n30pro.bak`)→ 把 root 的登录 shell 换成 zsh。

```sh
exec zsh          # 立刻进入新 shell(或重新 SSH 登录)
```

常用附加参数:

```sh
... install.sh -- --mirror        # 走 Gitee 镜像,国内更快
... install.sh -- --theme agnoster
... install.sh -- --uninstall     # 反悔了:卸载并还原
... install.sh -- --dry-run       # 只看它会做什么
```

> 💾 **空间提醒**:oh-my-zsh 约占 20–30MB。装之前先看 `df -h /overlay`,
> 剩余不足 40MB 就别装(或者用 `--dry-run` 先看)。
> 🧩 如果 `zsh` 在你的软件源里找不到,先 `apk update` 换个可用的源再试。

### B5.3 ⭐ 第二个任务:一键装"其他"

```sh
BASE=https://raw.githubusercontent.com/markternu/openwrtnetcoren30pro/main

# 只装常用工具(nano/htop/curl 等)+ 自动跑一次 USB 自检

```

> ⚠️ 装 OpenClash/PassWall 需要内核模块支持 —— **本项目固件已经内置**(`kmod-tun`、
> `kmod-nft-tproxy` 等)。如果你刷的是别的固件,这里会报"未提供",那就不是本项目的问题了。

### B5.4 开 WiFi

新系统里 WiFi 默认是**关闭**的(需要手动开):

* LuCI → **网络 → 无线** → 点 **radio0 / radio1** 的"启用" → 编辑 → 填 SSID/密码 → 保存并应用。

### B5.5 确认端口

* `ip -br link` 应看到 `lan1 lan2 lan3 lan4`(物理口)与 `eth1`(WAN);
* 我们的固件已内置默认映射:**LAN = lan1~lan4,WAN = eth1**;
* 如果是从旧配置升级来的,端口可能沿用旧配置 —— 全新刷机就是默认值。

### B5.6 顺手做的事

```sh

uci commit system
/etc/init.d/system restart
```

## B6 让中兴 F50 上网

### B6.1 插入 F50

1. F50 先**独立开机、确认它自己能上网**(指示灯稳定);
2. 用**尽量短**的 USB 数据线插到路由器 USB 口;
3. 等 10–20 秒,在路由器上查看:

```sh

```

> 如果完全没有反应 → USB 供电或线材问题:换短线、确认 F50 已进入"USB 共享"模式。

### B6.2 把 WAN 指向 F50


## B8 想回原厂系统怎么办

前提:B2 备份过 `mtd5_ubi.bin`。

* **u-boot TFTP 方式**:把备份的 `mtd5_ubi.bin` 改名成 u-boot 期望的名字放进 TFTP,进恢复模式写入;
* **进内存系统手动写**:用 `initramfs.itb` 启动到内存系统 → 把 `mtd5_ubi.bin` 传进去 →
  `mtd write mtd5_ubi.bin ubi`(或用 u-boot 里对应命令)→ 重启;
* 若连原厂 u-boot 也想要回去:用 TTL 写入备份的 `mtd4_FIP.bin` 与 `mtd1_BL2.bin`。

> 本项目固件**不碰 FIP/BL2**,所以只要你不去"换回 u-boot",回原厂系统只需要写 `ubi`。

# 第三部分 日常维护

### 以后升级固件

* **系统内升级(推荐,已修复)**:把新固件传到路由器 → `sysupgrade <文件>`;
  报"设备不兼容"就加 `-F`;想恢复出厂设置加 `-n`。
* **TFTP 整刷(保底)**:照着 B4 再来一遍。
* 升级前建议在 LuCI → 系统 → 备份/恢复 里导出一份配置。

### 配置备份

```sh
# 路由器上
sysupgrade -b /tmp/backup-$(date +%F).tar.gz
# Mac 上拉回来
scp -O root@192.168.1.1:/tmp/backup-*.tar.gz ~/n30pro-backup/
```

### 救砖三级方案

| 严重程度 | 现象 | 处理 |
|---|---|---|
| 轻 | 系统起不来但 u-boot 还在 | TFTP 整刷(B4) |
| 中 | 想临时进系统看看 | u-boot 走 `boot_recovery`,拉 `initramfs.itb` 进内存 |
| 重 | 改坏了 FIP/引导 | TTL 串口 → 拉 initramfs → 重写 FIP(B3.5) |
| 最重 | BL2 也坏了 | 需要编程器/官方工具,属于专业维修 |

# 附录 B 症状→原因→解决 对照表

| 症状 | 可能原因 | 解决 |
|---|---|---|
| 原厂系统 sysupgrade 报 `Image slot 0/1 was marked invalid` | 原厂 u-boot 签名校验 | 必须先换 u-boot(B3) |
| TFTP 只有 19 字节回包 | 文件名与 u-boot 请求不一致 | 按 `tcpdump` 抓到的 RRQ 名改名 |
| 路由器反复请求但收不到数据 | ①路由漂到 wlan0 ②rp_filter≠0 | A5.4 第 3 步 + 第 4 步 |
| 树莓派本机自测成功、路由器却不行 | 就是网络路径问题(rp_filter/路由) | 同上,别怀疑 tftpd |
| 刷完版本没变、包还是旧的 | 走错升级分支(写进了 `kernel` 卷) | 用 TFTP 整刷(B4);本版固件已修好 sysupgrade |
| 刷完 SSH 提示 no root password | 全新系统,未设密码 | `passwd` 设置 |
| 刷完 WiFi 搜不到 | 新系统无线默认关闭 | LuCI → 网络 → 无线 → 启用 |
| 刷完没网 | WAN 没指向正确设备 | LuCI → 网络 → 接口 → WAN 设备选 `eth1` 或 F50 的 `usb0` |
| F50 插上完全没反应 | 供电/线材/F50 未进共享模式 | 换短线、F50 先独立联网、确认进入 USB 共享 |
| `apk add` 报内核模块"未提供" | 内核模块与内核 ABI 绑定 | 用本项目固件(已内置),不要从仓库找 kmod |
| 找不到树莓派 IP | 主机名解析失败 | 路由器 DHCP 列表 / `arp -a` |
| SSH 提示 host key 变化 | 重装过系统 | `ssh-keygen -R <IP>` |
