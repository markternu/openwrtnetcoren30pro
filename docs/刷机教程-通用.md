# Netcore N30 Pro — USB 供电修复固件 · 刷机教程

> ⚠️ **本轮(第二轮)重要提示**:上一轮固件"刷机成功但未生效"的原因已查明并修复——
> 设备身份 `netcore,n30pro` 不在 `platform.sh` 的 `fit_do_upgrade` 白名单里,
> 系统内 sysupgrade 把镜像写进了 `kernel` 卷,而 u-boot 只从 `fit` 卷引导。
> **本轮推荐用 u-boot TFTP 整刷**(用 `firmware/immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb`,
> 文件名与 u-boot 的 `bootfile_fw` 完全一致);系统内 sysupgrade 也已同步修好。
> 刷完请先跑 `grep DISTRIB_REVISION /etc/openwrt_release`(应为 `r37877-n30pro`)与 `usb-fix-check` 确认生效。
> 详见《第二轮交付说明-根因修复.md》。

> 📦 **第三轮(最新)**:已把 openclash / passwall 需要的 `kmod-tun`、`kmod-nft-tproxy`、
> `kmod-nft-socket`、`kmod-inet-diag`、`kmod-netlink-diag`、`kmod-nft-nat`、
> `kmod-nf-reject(6)`、`kmod-nft-fib` 编译进固件(这些包官方仓库里没有,原因是其内核配置默认不开启,
> 且内核模块必须与内核 ABI 匹配)。本轮内核配置有变化,**必须整机刷入**(旧镜像上无法单独装这些 kmod)。
> 详见《第三轮交付说明-补齐代理内核模块.md》。


本教程配套《README-交付说明.md》中的固件与补丁,适用于已能正常运行 ImmortalWrt 的
**磊科 Netcore N30 Pro**(MT7981B,原厂/官方 ImmortalWrt u-boot 或带 WebUI 的第三方 u-boot 均可)。
网络拓扑与踩坑经验请参考同目录既有资料《netcore-n30pro-full-retrospective-guide.md》。

## 1. 刷机前必做:备份原厂/当前分区

> 重要:刷机前务必先备份,方便随时救砖回退(参照回顾文档“后悔药”一节)。

路由器 SSH 登录(默认 `root`,无密码或已设置的密码)后执行:

```sh
mkdir -p /tmp/backup
cat /proc/mtd
# 按 /proc/mtd 实际设备名备份(通常为):
dd if=/dev/mtd0 of=/tmp/backup/mtd0_BL2.bin
dd if=/dev/mtd1 of=/tmp/backup/mtd1_u-boot-env.bin
dd if=/dev/mtd2 of=/tmp/backup/mtd2_Factory.bin
dd if=/dev/mtd3 of=/tmp/backup/mtd3_FIP.bin
dd if=/dev/mtd4 of=/tmp/backup/mtd4_ubi.bin      # 这就是“整个系统”,V2/官方都在这
```

再用 `scp -O`(老协议,救援系统没有 sftp-server 时必须加 `-O`)或 WinSCP 拉到电脑保存。

## 2. 方式 A(推荐):系统内 sysupgrade 升级

前提:路由器当前能正常启动进入 ImmortalWrt(你现在刷的 SamZong V2 就满足)。

把 `.itb` 传到路由器(电脑→路由器,或用 `wget` 从本机 http/tftp 拉):

```sh
scp -O ./firmware/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb root@192.168.1.1:/tmp/
```

SSH 进路由器执行:

```sh
# 先校验 MD5/SHA256 与发布值一致
sha256sum /tmp/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb

# 保留现有配置升级(推荐先试这个):
sysupgrade /tmp/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb

# 若报“设备不兼容 / device not supported”,说明板子仍被识别为 netis NX30V2 等旧名,加 -F 强制:
#   sysupgrade -F /tmp/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb
# 想要彻底干净(避免 V2 遗留的 /etc/board.json 端口映射残留),可加 -n 重置配置:
#   sysupgrade -n -F /tmp/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb
```

等待 2-4 分钟,`ping` 通后重新 SSH。

> ⚠️ 回顾文档关键经验:刷完/改完配置后,**先用 `reboot` 正常重启验证配置持久化,再断电**;
> 直接拔电源容易损坏 overlay,导致起不来。

## 3. 方式 B:u-boot 下 TFTP 救砖/整机重刷(可随时用于救砖)

适用:变砖、没进系统、或想从 u-boot 直接整刷。
你需要一台 TFTP 服务器(树莓派/电脑均可),路由器 u-boot 会自己来 TFTP 拉文件。

1. **文件命名**:先别猜,开机进 u-boot 后用抓包确认它请求的确切文件名:

   ```sh
   # 在 TFTP 服务器上抓包(eth0 接路由器,静态 IP 如 192.168.1.254)
   sudo tcpdump -i eth0 -n udp port 69
   ```

   路由器:拔电源 → 按住 Reset → 插电源 → 保持约 10 秒 → 松开,进入 u-boot TFTP 恢复模式。
   看到类似 `RRQ "immortalwrt-mediatek-filogic-xxxx-squashfs-sysupgrade.itb"` 后,
   **把我们的固件复制一份改成抓到的这个名字**:

   ```sh
   sudo cp ./firmware/immortalwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb \
           /srv/tftp/immortalwrt-mediatek-filogic-<抓到的名字>.itb
   ```

   > 已知官方 netis_nx30v2 u-boot 请求的是 `immortalwrt-mediatek-filogic-netis_nx30v2-squashfs-sysupgrade.itb`。
   > 19 字节的 UDP 回包 = “文件不存在”,不是传输;正常应是 1000~1472 字节的 DATA 包(详见回顾文档)。

2. 传输完成(出现小于 1472 字节的最后一个 DATA 包)后,u-boot 会写入 flash 并重启;
   等 1-2 分钟 ping + ssh 测试。

3. 如果你用的是带 WebUI 的第三方 u-boot(Yuzhii0718 等),则直接在网页上传
   `openwrt-mediatek-filogic-netcore_n30pro-squashfs-sysupgrade.itb`(或等价的 netcore_n30pro 名)即可。

## 4. 刷机后验证:USB 供电是否恢复

```sh
# 1) 内核不再出现 dummy regulator 提示
dmesg | grep -i "supply bus not found"        # 应无输出
dmesg | grep -iE "usb|xhci|regulator"          # 应能看到 xhci-mtk 正常 probe

# 2) VBUS 已上电:插上任何 USB 设备(如手机/充电指示灯设备),应能看到设备指示灯亮

# 3) 枚举正常:插上中兴 F50(先把 F50 调到“USB 共享网络”模式,指示灯不再闪烁)
lsusb                                          # 应看到新增 VID/PID(中兴设备)
dmesg | tail -30                               # 出现 new high-speed USB device ... usb 1-1
ip link                                        # 出现 usb0 / eth2 之类的新网卡(= F50)

# 4) U 盘测试(可选)
ls /sys/bus/usb/devices/                       # 除 usb1/usb2 外应多出 1-x 设备
```

说明:中兴 F50 属于“USB 网络共享”设备(走 cdc_ether/rndis),上电并正确枚举后内核自动生成网卡,
名称一般为 `usb0` 或 `eth2`。若只见 `usb0` 而网络不通,多为 F50 侧未进入共享模式或线材/供电问题:
- 请使用**尽量短**的数据线(社区实测长线/劣质线会导致供电不足、反复掉线);
- F50 需先开机并联网、再插 USB(见第 5 节)。

## 5. 中兴 F50 作为 WAN 上网(让路由器用 F50 的网络)

1. F50 开机 → 连好它的 Wi-Fi/确认能上网 → 用数据线接入路由器 USB 口
   (部分 F50 需在其 App/管理页打开“USB 网络共享”,不同固件开关位置不同)。
2. 路由器 LuCI:`网络 → 接口 → 编辑 WAN`,
   把“设备/设备(Device)”从 `eth1` 改为上面查到的 `usb0`(或 `eth2`),协议保持 DHCP 客户端;
   WAN6 同理(或删除)。保存并应用。
3. 此时路由器即可经 F50 上网,其余 LAN/WiFi 客户端无需任何改动。

> 若 LuCI 里看不到 `usb0`/`eth2` 选项,回到 SSH 确认 `ip link` 有该接口且 `lsmod | grep usbnet` 有输出;
> 若 F50 在别处(电脑)共享正常而在路由器上不识别,优先怀疑线材长度/供电,而非驱动。

## 6. 善后与注意事项(回顾文档浓缩)

- 刷机后先 `reboot` 验证,再考虑断电;
- 两个设备 IP 撞车(路由器 192.168.1.1 vs 主路由 192.168.1.1)会引发各种“诡异”网络问题,
  刷机时建议把测试链路与日常链路分开;
- 想回退 V2 / 官方:TFTP 里改名刷回即可;有备份分区的直接 u-boot 恢复 mtd5_ubi.bin。

## 8. 关于"会不会变砖"(安全性说明)

**结论:最坏情况是"刷完不满意,回退重刷",不存在刷成硬砖的路径。** 依据如下(均可自查):

1. **sysupgrade / u-boot TFTP 只写 `ubi` 分区**(偏移 `0x580000`,大小 `0x7280000` ≈ 120MB),
   而 **BL2 / u-boot-env / Factory / FIP(U-boot 本体)分区完全不被触碰** —— 这是由设备树分区表决定的,
   本固件的分区表与你已成功刷入的 V2 **逐字节一致**(已用 dtc 对比:u-boot-env@0x100000、Factory@0x180000、
   FIP@0x380000、ubi@0x580000,偏移与长度全部相同)。只要 Bootloader 没被动,就永远能救。
2. 本镜像的 **FIT 结构与你已刷入过的 V2 镜像完全一致**(内核加载地址 0x44000000、DTB 加载地址 0x43f00000、
   gzip 内核、squashfs rootfs、config-1 配置节点都相同),唯一差别是内容与哈希 —— 也就是说,
   它和你"已经刷成功过一次"的镜像是同一类东西,不是未知格式。
3. 镜像只有 14.0 MiB,远小于 120MB 的 ubi 分区,不存在写溢出。
4. 你手上还有两道保险:**u-boot 的 TFTP 恢复模式**(与系统内容无关,一直可用)和**之前备份的 `mtd5_ubi.bin`**
   (u-boot 下传回即可恢复原厂系统)。本目录还额外提供了同版本 `initramfs.itb`。

**真正的风险不是"变砖",而是"刷完没达到预期"**(例如 USB 仍不供电、或某个服务配置与 V2 不同),
这类问题都可以用 `sysupgrade` 再刷回来或走 u-boot TFTP 覆盖,不会损坏设备。

### 建议的稳妥顺序

1. 先按第 1 节备份分区(若还没备份,这一步必做);
2. 用**保留配置**的方式刷:`sysupgrade <固件>`(不加 `-n`);
3. 能正常开机、SSH 正常 → 再验证 USB(第 4 节);
4. 只有在你确认新固件满意、或需要"干净重来"时,才用 `sysupgrade -n -F` 或 u-boot TFTP 全新刷。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| sysupgrade 报 “The device is not supported” | 加 `-F` 强制(镜像分区表与 V2 完全一致,安全) |
| 刷完 USB 仍无供电 | 先确认刷入的确实是本 .itb(看版本/看 dmesg 无 dummy 行);个别批次主板若仍无电,联系确认硬件 |
| F50 插上没反应 | F50 开机联网后再插;换短线;确认进入 USB 共享模式 |
| 想恢复出厂/重刷 | 走方式 B TFTP 或 `sysupgrade -n -F` |
